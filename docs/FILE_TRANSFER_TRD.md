# MinMD 文件批量与单文档导入导出 TRD

日期：2026-10-16 · 状态：当前实现范围与验收要求

## 1. 目标与现状

在前台提供文件多选、批量压缩包导入导出，并统一单文档的导入导出体验。使用 minmd 完整格式搬运内容时保留当前支持的样式、目录和附件；使用 Markdown 时优先满足通用软件交换需求，明确提示样式损失。

文档菜单提供完整格式与 Markdown 导出，导入自动识别单文档包或 Markdown；文件列表提供多选和批量导出，统一上传入口识别带清单的 ZIP。单文档替换通过既有协作接口创建版本并推进 epoch。文件创建人由 `createdBy` 记录，尚无独立的最后更新人字段。本文说明当前实现的格式、边界与验收要求。

本方案替代此前讨论的后台空间迁移方案。本次不增加后台导入导出入口，不创建新空间、不选择空间负责人。用户在当前空间选择文件导出，在目标空间的当前目录导入；全选根目录文件及文件夹即可搬运空间当前内容。

## 2. 范围

### 2.1 本期包含

- 文件列表多选、全选当前列表、清空选择及批量导出。
- 递归导出选中的文件夹及其后代，保留目录结构和相对顺序。
- 批量导出支持 minmd 完整格式和 Markdown 两种文档格式。
- 统一上传入口识别 minmd 完整包、Markdown 包及现有单文件类型。
- 批量导入到当前目录，全部新建，不覆盖现有文件。
- 单文档菜单统一为「导入文档」「导出文档」。
- 附件打包、引用映射、格式校验、权限检查、失败清理及进度反馈。

### 2.2 本期不包含

历史版本、回收站、成员与角色、原作者身份、分享权限及链接配置、AI 密钥、通知、收藏和访问记录均不迁移。不做后台空间备份、覆盖合并、断点续传、持久任务中心或任意 ZIP 解包。不承诺跨应用版本兼容，不迁移协作会话、个人撤销栈及客户端缓存。

批量移动、删除和复制不因本次增加多选而自动纳入范围。部署层整库备份继续使用现有维护命令。

## 3. 格式与保真

| 导出格式               | 文档                                                                           | 表格                                         | PPTX、PDF、图片、视频  |
| ---------------------- | ------------------------------------------------------------------------------ | -------------------------------------------- | ---------------------- |
| minmd 完整格式（默认） | 编辑器原生结构化内容，保留当前支持的字体颜色、背景高亮、字号、块属性及图片布局 | 保留当前权威工作簿数据、公式和已有支持的格式 | 原文件及必要的预览信息 |
| Markdown               | `.md`，保留标题、列表、代码等可表达结构                                        | `.xlsx`，沿用现有转换能力及兼容边界          | 原文件                 |

完整格式不得经 Markdown 或 XLSX 中转。不把旧账号 ID、旧文件 ID、旧协作状态直接接入目标空间；导入时从经校验的内容重新初始化协作状态。

Markdown 无法保留自定义字体颜色、背景色、字号、完整高亮块、折叠块及图片布局等信息。沿用已有转换规则并在弹窗中提示；不能承诺重新导入后恢复这些样式。表格转 XLSX 也应遵循现有转换限制。

### 3.1 文件扩展名与包结构

- minmd 单文档和批量导出统一使用 `.minmd.zip`，均包含格式清单；单文档包仅有一个文档及其依赖附件。
- 批量 Markdown 使用 `.zip`，包含格式清单、按目录组织的文件及本地附件。
- 单文档 Markdown 没有需要打包的本地图片时下载 `.md`；包含本地图片时下载带清单的 `.zip`。弹窗预先说明下载类型。
- 两种 ZIP 使用同一套受限封装格式，通过清单识别，不能仅凭扩展名认定可信。

清单至少记录格式标识、包格式版本、应用版本、导出时间、导出模式、文件树、包内文件标识、内容类型、必要的内容 schema 版本，以及附件的 MIME、大小和 SHA-256 校验和。包内标识只用于解析和重建，不作为目标数据库 ID。

完整包内部按标识保存内容和附件，文件原名记录在清单。Markdown 包保留适合人阅读的目录与文件名，处理非法字符及同名冲突后同步修正相对图片路径。

第一版只承诺同一应用版本的往返导入。未知包版本、引擎或内容 schema 必须明确拒绝，不能尝试后静默丢弃字段。

## 4. 前台交互

### 4.1 批量选择与导出

1. 文件列表提供「选择」入口，进入选择模式后显示复选框和批量操作栏。
2. 「全选」明确表示当前筛选后的列表，不表示整个空间；切换空间或所在目录时清空选择。
3. 选中文件夹时导出其完整子树；同时选择祖先和后代只导出一次。选中具有子文件的文档时同样保留其后代结构。
4. 导出弹窗显示选择范围，选择「minmd 完整格式（默认）」或「Markdown」，展示保真说明后开始。
5. 服务端展开文件树、检查权限及资源限制，返回实际文件数量和处理进度；准备完成后提供下载。

保留相对层级；未被选中的祖先不一并导出。移动端使用相同能力，批量操作栏保持紧凑，较少使用的操作收进更多菜单。

### 4.2 批量导入

现有「上传文件」入口增加支持包类型的说明。选文件后自动识别，不再增加一套独立上传入口。

流程：选择文件 → 上传与校验 → 显示包名称、模式、文件数量、目标位置和样式提示 → 确认导入 → 显示结果。校验阶段不创建正式文件。

- 目标为当前空间、当前目录；确认前可返回取消。
- 全部创建新 ID，同名自动添加后缀，不覆盖、不合并。
- 批次失败整体不发布，不显示部分成功；提交成功后刷新目录并显示导入数量。
- 原有 `.md`、`.xlsx` 及媒体单文件上传行为保留。
- 第一版只接受本系统生成且带有效清单的 ZIP。普通 ZIP 提示不支持，不能扫描压缩包后随意执行导入。

### 4.3 单文档

- 「导出文档」打开格式选择弹窗，默认完整格式；导出前等待当前用户待提交修改得到服务端确认，失败时不能宣称已导出最新内容。
- 「导入文档」自动识别 `.md`、`.markdown`、单文档完整包或单文档 Markdown 包。
- 单文档入口遇到多文件包时，提示使用文件列表的上传入口，不选择其中一个文档静默导入。
- 导入当前文档只替换正文及正文依赖附件，保留文件 ID、标题、目录、创建人和现有访问权限；清单中的源标题不自动覆盖当前标题。
- 替换前明确确认，沿用原有内容导入服务和版本机制。成功创建新版本、推进 epoch，并让其他协作会话重新加载；失败保留原内容和附件。
- 导出包不携带历史，不影响目标文档在替换时按现有策略保留恢复版本；版本数量继续遵循现有限额。

## 5. 身份、权限与时间

- 批量导入以当前前台账号作为新文件、文件夹的创建人及附件上传人，不保留原作者、不按账号或昵称自动匹配用户。
- 当前没有最后更新人字段，本次不单独引入；后续如增加，新建导入文件的初始更新人同样为导入账号。
- 清单保留源文件创建及更新时间；完整包新建导入时保留这两个业务时间。实际导入时间单独记录。缺少源时间的独立 Markdown 文件使用导入时间，Markdown 包按清单取值。
- 单文档替换沿用既有身份和更新时间语义，不能将源文件的创建人或时间覆盖到现有文件。
- 新文件默认私有，不继承源文件分享配置；仍遵循目标空间现有成员访问规则，不能把「私有」误解为仅导入者可访问。
- 只有已登录的前台用户能执行；导出逐个验证文件及关联附件的读取权限，导入验证目标空间、目录的创建和附件上传权限，替换验证编辑权限。
- 选择中任一项或递归子项不可读取时，拒绝本次导出并给出不泄露正文的提示，不静默跳过。任务创建、下载及正式提交时均重新校验身份和权限。
- 不通过前台按钮是否可见代替服务端授权；后台空间查看权限不用于前台导出。

## 6. 一致性、附件与链接

### 6.1 导出快照

不暂停整个空间写入。先固定本次选中目录的文件集合及结构，再逐个捕获服务端已接收、可持久恢复的完整内容。文档须包含尚未合并进检查点的持久更新，表格须以服务端权威状态为准，不能直接读取过期投影。

各文件允许来自不同时间点，不承诺整个空间同一时刻的快照。未到达服务器的其他用户本地输入不在导出范围。导出不会为每个文件额外制造历史版本。

捕获后内容、元数据和附件引用须固定，打包期间继续编辑不改变已捕获的数据。文件被删除、权限变化或附件不可用且无法完成一致读取时明确失败。附件在导出任务期间需有临时引用保护或受控副本，避免被并发清理。

### 6.2 引用重建

- 同一附件在包内去重；文档中的 assetId、私有附件路径及媒体文件引用在导入时统一重建。
- 完整格式处理当前所有已支持节点和附件字段；包含未知节点或不支持的属性时拒绝导入，不以忽略属性实现“成功”。
- 包内被包含文件之间的已知文档引用和内部链接映射到新 ID；未被包含的目标保留原地址，不自动授予目标权限，也不承诺在另一套部署中可访问。
- 外部链接保持原样，不主动下载外部图片或网络资源。
- Markdown 本地图片只解析包内允许路径；图片缺失、校验失败或引用越界时明确失败，不留损坏引用。
- PPTX、PDF、图片和视频包含原文件，重新建立预览与下载关联，不能只复制原服务器的 URL。

## 7. 后端处理与失败恢复

复用现有 Fastify、TypeBox、前台身份、文件权限、附件存储、文档内容导入及表格协作服务。业务逻辑放 `apps/app_server`，不增加平行鉴权或请求层；单文档与批量流程共享格式校验、内容转换和附件映射能力。

采用轻量异步任务返回进度、结果及受权限保护的下载，不引入持久任务中心和断点续传。进程重启时未完成任务可重新提交，残留暂存文件按规则清理。接口实现时通过 OpenAPI 生成契约，不维护另一份手写接口目录。

- ZIP 流式写入或受限暂存，不能把整个空间及附件一次性读入内存。
- 先完成包校验与附件暂存，再在事务中建立文件树、正文和引用；提交前结果不可在正常目录中见到。
- 数据库与文件系统不是一个事务：提交前准备好所有可读附件，数据库回滚时清理新写文件，异常重启后清理未引用的残留，不触碰原附件。
- 重复确认和网络重试沿用同一批次标识，避免请求成功但响应丢失时重复导入；用户主动再次发起导入可创建另一份副本。
- 临时下载文件绑定创建用户，设置有效期，完成或过期后清理；失败反馈使用现有 AppError，日志不写正文及完整压缩包内容。

## 8. 资源与压缩包安全

以下默认值由 `config/file-transfer.ts` 统一校验，在 `.env.example` 中提供配置说明：

| 限制                                 | 建议默认值                          |
| ------------------------------------ | ----------------------------------- |
| 导入包压缩体积、导出包最终体积       | 200 MiB，与现有统一上传上限保持一致 |
| 解压后总容量                         | 1 GiB                               |
| 每批业务文件及文件夹数量             | 1,000                               |
| 压缩包条目数量（含内容、附件及目录） | 5,000                               |
| 目录嵌套深度                         | 32 层                               |
| 每账号同时处理任务数                 | 1                                   |
| 单任务累计处理时限（不含等待确认）   | 10 分钟                             |
| 临时下载包有效期                     | 30 分钟                             |

导出压缩后仍超过上限时提示缩小选择范围，不自动拆包。JSON 内容继续受各编辑引擎已有规模限制约束；200 MiB 上传上限不表示任意大小的文档或工作簿都能载入。

拒绝绝对路径、路径穿越、符号链接、重复条目、加密包、任意嵌套归档及非法文件类型。XLSX、PPTX 等允许的业务文件按原文件校验和处理，不作为嵌套导入包递归解压。流式累计实际解压大小，不信任 ZIP 声明的容量。校验清单引用闭合、文件内容、MIME 和校验和，不能将包内路径用于指定服务器写入位置。

## 9. 演示版与部署影响

正式能力需要服务端处理。本期 GitHub Pages 演示中相关入口保留为禁用态，并提示“部署后可使用”；已有本地单文档 Markdown 导入导出继续可用。纯前端完整包演示不在本期范围。

沿用单后端服务及现有附件目录，不新增对外端口、独立部署服务或 Docker 组件。新增业务表或字段按现有迁移流程落地，不重写既有迁移。

## 10. 验收标准

| 场景         | 必须满足                                                                                 |
| ------------ | ---------------------------------------------------------------------------------------- |
| 完整格式往返 | 字体颜色、背景高亮、字号、列表、表格、代码、Mermaid、图片大小与对齐等已支持属性保持一致  |
| 表格往返     | 多工作表、公式、格式、合并等已有能力保持一致，重新打开和多人编辑正常                     |
| 附件往返     | 正文图片正常显示，PPTX/PDF/图片/视频预览和下载可用，原文件校验和一致                     |
| 目录选择     | 多选、全选、递归、祖先后代去重、同名后缀和相对层级正确                                   |
| Markdown     | 显示样式损失提示，代码和基础结构正确，本地图片相对引用可在包外查看并重新导入             |
| 身份与权限   | 新建归当前账号；跨空间、无权限后代、失效会话及过期下载均拒绝，不泄露私有内容             |
| 单文档替换   | 保留标题与目录，失败不修改原文档；旧版本可恢复且图片不丢失                               |
| 多人协作     | 导出无过期投影；导入替换后旧 epoch 不覆盖新内容，其他会话可恢复编辑                      |
| 并发与重试   | 导出期间编辑、移动、删除及附件清理均有明确结果；重复请求不生成重复副本                   |
| 失败与边界   | 损坏包、非法路径、未知格式、超限、缺失附件、数据库失败和进程重启不产生半成品或破坏旧内容 |
| 界面与回归   | 桌面、移动端、键盘及进度提示可用；现有上传、保存、版本限额、正式构建和演示部署不回归     |

实施验收需运行类型检查与相关行为测试；涉及数据库、附件和权限的部分使用独立 `_test` 库做集成测试，并完成真实浏览器的导出—导入往返。构建成功或仅校验包结构不足以证明保真。

## 11. 实现位置

- `apps/app_server/src/modules/file-transfer/`：压缩包格式、受限读写、逐文件快照及校验、任务、批量新建与单文档替换。
- `apps/app_server/src/database/schema/file-transfers.ts`：成功导入的幂等结果及实际导入时间；新增迁移保留在 `database/migrations/`。
- `shared/document/`、`shared/spreadsheet/`：前后端共用的 Markdown、XLSX 转换，原前端入口保留兼容导出。
- `apps/web/src/components/FileTransferDialog/`：格式选择、校验摘要、目标位置、进度、重试与确认。
- 文件列表、文档菜单和现有上传弹窗接入同一传输能力，演示版保留本地 Markdown 路径。

测试命令和独立数据库要求见 [开发指南](DEVELOPMENT.md)。实现变更后按第 10 节验收，不能用构建成功代替往返及协作检查。
