# MinMD 技术需求文档（TRD）

版本：v0.2 · 日期：2026-10-12 · 状态：本期范围已实施并完成单实例验收

## 1. 目标与现状

MinMD 是可自行部署、计划开源的轻量文档空间。前台交互参考飞书，界面紧凑，支持文档、表格、PPTX、文件树、多账号和空间。管理后台复用 MAS 脚手架，不另建管理系统。

当前工程采用 Bun workspace，前台位于 `apps/web`，后端与管理后台基于 MAS。账号、空间、文件树、私有附件、分享和 AI 接口已接入服务端；文档采用 Tiptap / Yjs / Hocuspocus，表格采用 FortuneSheet 与服务端权威引擎，均默认最多 10 个编辑会话。旧演示数据保留并提供主动导入入口。本期范围已通过专用数据库、真实协作连接和浏览器验收；单实例 Docker 空库部署、HTTPS/WSS、附件及历史备份恢复已验证。运行规模、性能和编辑器兼容边界见 README，长期离线协作与多实例扩容仍不在本期范围。

本期目标：把现有前台接入真实认证、空间、文件与内容存储，完成文档与表格多人实时协作、简单版本管理、分享、API / MCP 和 Docker 部署。文档协作先落地，表格协作后置但属于本版必交付项，不能以单人编辑作为本版完成状态。

### 1.1 本期范围

- 多账号、空间与成员归属，复用 MAS 账号和系统权限能力。
- 文件夹与父子文档树、移动排序、收藏、最近访问、回收站。
- 文档与表格多人实时协作、在线成员和光标 / 选区、断线重连及可靠持久化。
- 文档与表格版本历史、只读预览、备注和恢复；图片和 PPTX 上传、读取与下载。
- 公开 / 私有分享、密码、有效期及访客只读页面。
- API Key、业务 API 和 MCP 读写接口。
- 单仓库工程整合、数据库迁移、Docker Compose 和备份恢复说明。

### 1.2 不在本期范围

- 长期离线协作、多地域部署、多协作服务副本和逐字 / 逐单元格版本差异比较。
- 复杂权限继承、多级审批工作流、匿名编辑。
- PPT 编辑和动画播放；旧版 `.ppt`、`.xls`。
- 完整 Excel 高级对象转换、图表 / 透视表 / 宏兼容。
- 内置 AI 模型、聊天界面和模型供应商密钥管理。AI 接入指外部客户端通过 API / MCP 操作 MinMD。
- 文档查找替换、PDF 导出、文件批量操作等纯前端增强，见根目录 `TODO.md`。

## 2. 工程结构与技术方案

### 2.1 单仓库结构

```text
minmd/
├── apps/
│   ├── web/                         # 现有 MinMD 前台
│   ├── web-cms/                     # MAS 管理后台
│   └── app_server/src/
│       ├── modules/                 # MinMD 业务模块
│       └── database/schema/         # 业务数据表
├── system/server/                   # MAS 通用认证、权限、配置等能力
├── config/                          # 前后台权限目录等配置
├── database/migrations/
├── deploy/                          # Docker、Compose、代理配置
├── scripts/
├── docs/
├── app.config.ts
├── package.json
└── bun.lock
```

- 使用 Bun workspace，只有根目录维护依赖锁文件和 Git 仓库。
- 从 MAS 指定提交引入必要源码，记录上游 URL、提交 SHA 和许可证；不复制上游 `.git`、凭证、数据库、备份、运行目录及 `node_modules`。
- 保留现有前端改动和主题变量；迁移期间不顺带重构编辑器。
- 沿用 MAS 的模块注册、数据库连接、配置校验、错误处理和 TypeBox 契约；业务实现放 `apps/app_server`，系统模块不反向依赖业务。
- `app.config.ts` 指向统一业务 schema 导出入口，包含账号表和 MinMD 业务表。
- 接口目录由 OpenAPI 生成。本文件的接口表是预期设计，实际路由契约以实现生成的 OpenAPI 为准。

### 2.2 技术栈

| 层 | 方案 |
|---|---|
| 前台 | 现有 React、TypeScript、Vite、Hash Router、Zustand、Ant Design、Less Modules |
| 编辑器 | 保留 Tiptap 和现有 PPTX 渲染器；FortuneSheet 1.0.4；兼容转换旧 Univer 快照 |
| 文档协作 | Tiptap Collaboration + Yjs + 自托管 Hocuspocus 4.7.0；正式房间鉴权，PG 权威状态及更新日志 |
| 表格协作 | FortuneSheet 1.0.4 + 服务端权威操作引擎；稳定行列身份、旧坐标映射、个人撤销及 PG 持久化；默认每表格 10 个编辑会话 |
| 后端 | Bun、Fastify、Drizzle、PostgreSQL，沿用 MAS |
| 契约 | TypeBox 请求 / 响应 Schema，OpenAPI；前端通过集中请求模块调用 |
| 附件 | 私有文件目录 + 数据库元数据 + Docker 持久化卷 |
| MCP | 官方 TypeScript SDK，Streamable HTTP，复用业务服务 |
| 部署 | Web 反向代理、应用服务、PostgreSQL；同源访问 |

文档和表格协作使用单应用实例和 PostgreSQL，不依赖 Redis 或托管协作服务。房间队列及缓存位于单个应用进程，当前不能将应用扩成多个副本。附件存储封装读取、写入、删除边界。

### 2.3 协作方案与选型门槛

- 文档使用开源自托管 Hocuspocus 和 Yjs，不以 Tiptap 托管服务作为运行依赖。[官方协作说明](https://tiptap.dev/docs/hocuspocus/guides/collaborative-editing)
- 表格编辑器使用 MIT 许可的 FortuneSheet 1.0.4，不引入 Univer Pro。正式服务端引擎维护稳定行列身份、操作队列、修订窗口、个人撤销、持久化和选区广播。开发验证入口仍独立存在，其能力不代表正式房间；当前规模和恢复边界见 README。[上游仓库](https://github.com/ruilisi/fortune-sheet)
- 阶段 1 完成表格协作技术验证：两个浏览器并发编辑、公式、插删行列、断线重连、服务端读取与写入、版本快照、私有部署及 Docker 依赖。
- 同期核实具体组件的许可证、分发边界、生产授权和费用；不购买或签订商业授权，不把开发试用凭证打进开源发布包。
- 官方方案若不满足开源、自部署或预算要求，必须在阶段 1 给出替换编辑器或自建协作层的独立决策，说明迁移与测试成本；不能把“自行给快照加 Yjs”视为已经解决表格协作。
- 表格 UI 和协作引擎通过页面适配边界连接。当前权威状态由服务端引擎维护并持久化至 PostgreSQL；AI 写入和浏览器操作共用该引擎，不能直接覆盖 FortuneSheet JSON。

文档开发验证入口使用 Yjs 二进制文件原子持久化、初始化单页面导入、持久化状态快照确认、10 会话限制和自动重连。验证与应用共享本机 WebSocket 入口，不增加独立端口。正式业务房间另行校验账号与空间权限，并将权威状态存入 PostgreSQL；标题与文件元数据通过业务接口保存。开发验证入口的配置和运行边界见 README。

### 2.4 协作数据通路

文档：浏览器 Tiptap ↔ Yjs Provider ↔ Hocuspocus 房间 → PostgreSQL 协作持久化。表格：浏览器 FortuneSheet ↔ 已验证的表格协作服务 → 对应权威持久化。两种引擎共享身份校验、文件元数据、附件、历史版本与 AI 授权，协议和引擎状态不强行统一。

JSON / Markdown / XLSX 是内容读取、导入导出及版本预览格式，不是实时协作协议。API / MCP 写入必须通过对应协作服务，禁止另外写一份 JSONB 与在线房间竞争。

## 3. 身份与访问规则

### 3.1 账号与后台

- 前台账号使用 MAS `app_users` 和前台会话；后台账号、角色、系统权限和审计沿用脚手架。
- 前后台身份严格分离，后台会话不能直接作为前台身份。
- 第一版账号默认由后台创建和管理；公开注册入口默认关闭，可通过明确配置启用现有注册能力。
- 前台采用 HttpOnly Cookie 会话，写请求携带 CSRF Token。生产环境使用 HTTPS，保留来源校验。
- 登录、退出、会话撤销、密码修改使用 MAS 现有流程，不另建认证框架。

### 3.2 空间权限

MAS 已有账号与系统角色权限；空间和成员关系是本项目新增业务，不假定脚手架已有空间实现。

| 身份 | 访问能力 |
|---|---|
| 空间负责人 | 使用空间文件、管理空间资料和成员、永久删除回收站文件 |
| 空间成员 | 默认只读；按文件授权编辑；创建者和空间负责人管理文件、分享与授权 |
| 访客 | 只读访问有效公开分享及其必要附件 |
| API Key | 在绑定空间内，根据只读 / 读写范围执行允许的接口 |

- 每个空间有一个负责人；负责人转移必须在事务内完成，不能移除最后一个负责人。
- 后台可管理空间和分配成员；前台提供空间创建、资料修改和负责人管理成员入口，成员从已有账号选择。
- 不自动授予后台身份读取任意私有正文的能力；管理操作按后台权限契约执行。
- 新文件默认私有、空间成员只读；创建者和空间负责人可管理。指定成员权限覆盖空间默认值；升级前旧文件保留成员可编辑行为。
- 所有资源查询校验当前身份和空间归属，不信任客户端提交的用户 ID。
- 移除成员后失去空间资格；若仍有单文件独立授权，继续按该授权访问该文件。绑定该成员创建的 API Key 仍在每次请求时检查空间成员资格。

### 3.3 分享语义

- 文件只有公开和私有两种可见性。私有允许空间成员及单独授权的空间外账号访问，授权不继承到空间目录或其他文件。
- 私有文件无有效访客链接；公开范围分为登录用户和所有人，可授予登录用户只读或编辑权限，匿名访客始终只读。公开链接保留密码、有效期、撤销与重置；独立成员授权不受公开链接密码限制。
- 无权限的登录用户可申请访问，只读用户可申请编辑；申请去重、取消和管理员审批均在服务端校验。审批添加单文件授权，不自动加入空间；结果通过站内通知告知。
- 正文、附件、版本和协作连接统一执行文件权限；权限降低时重验在线会话，只断开失去编辑权限的用户。只读访问不占编辑名额。
- 公开文件可额外设置密码、有效期；公开不等于自动加入公共文件索引。
- 分享显示文件当前已保存版本，不保存独立内容副本。
- 分享不继承到子文档、兄弟文件或父文件夹；正文中的文档引用独立检查目标访问权限。
- 第一版只分享文档、表格和 PPT，不公开分享文件夹。
- 文件进入回收站、分享撤销或过期后，正文和附件访客访问一并失效。

## 4. 业务模块与数据模型

### 4.1 模块划分

| 模块 | 职责 |
|---|---|
| `spaces` | 空间 CRUD、成员关系、负责人变更、空间访问校验 |
| `files` | 文件元数据、树结构、移动排序、删除恢复、列表查询 |
| `contents` | 内容初始化、读取投影、schema 与修订检查，不直接覆盖活跃协作状态 |
| `collaboration` | 文档 / 表格协作适配、房间认证、持久化确认、成员状态和会话撤销 |
| `versions` | 历史快照、备注、只读预览、恢复及历史附件引用 |
| `assets` | 图片和 PPTX 上传、文件读取、引用关系及清理 |
| `activity` | 每个账号的收藏、最近访问 |
| `shares` | 分享设置、Token、密码验证、访客授权 |
| `api-keys` | 密钥签发、哈希验证、范围和撤销 |
| `mcp` | MCP 工具映射、认证和协议适配 |
| `demo-import` | 本地演示数据一次性导入、ID 映射及结果报告 |

业务服务共用空间检查、文件树约束和版本写入规则。浏览器 API、API Key 接口和 MCP 不分别实现三套 CRUD。

### 4.2 数据表

表名为建议名称，迁移时沿用脚手架命名约定。

| 表 | 主要字段与约束 |
|---|---|
| `spaces` | `id`、名称、负责人账号、创建 / 更新时间 |
| `space_members` | 空间、账号、加入时间；空间与账号唯一 |
| `files` | `id`、空间、类型、名称、`parent_id`、`position`、创建者、公开状态、元数据版本、删除批次、删除时间 |
| `file_contents` | 文件 ID 唯一、引擎类型、内容 schema 版本、持久化修订号、读取投影及投影对应修订号 |
| `document_collab_states` | 文档 ID、Yjs 状态 / 更新记录、已持久化序号和内容 epoch；记录压缩保留可恢复检查点 |
| `file_versions` | 文件、持久化修订号、epoch、内容快照 / 引擎恢复数据引用、来源、操作人、备注、创建时间 |
| `version_assets` | 历史版本与附件引用关系，旧版本图片仍可读取 |
| `assets` | 空间、存储键、原文件名、MIME、字节数、校验和、上传人和时间 |
| `file_assets` | 文件与附件引用关系，用于授权和垃圾清理 |
| `file_favorites` | 账号与文件唯一 |
| `file_visits` | 账号与文件唯一、最近访问时间 |
| `file_shares` | 文件唯一、Token 哈希、密码哈希、有效期、撤销状态、分享配置版本 |
| `share_sessions` | 密码验证后的访客会话哈希、分享配置版本、到期时间 |
| `api_keys` | 创建者、空间、名称、前缀、密钥哈希、加密原文、显式操作权限集合、到期 / 撤销时间、最后使用时间 |
| `space_ai_policies` | 旧版策略迁移来源，运行时不再参与授权 |
| `demo_imports` | 账号、空间、导入幂等键、映射与进度，用于重复提交和失败重试 |

- 通用时间使用服务端 UTC 时间；客户端按时区显示。
- `files` 索引覆盖空间、父节点、排序和删除状态；收藏及访问记录按账号索引。
- 文档和表格内容不随文件树返回，打开文件时单独加载。
- `contentSchemaVersion` 表示数据格式；`revision` 标识服务端已持久化内容检查点，不能混用。实时协议自己的序号 / 状态向量不伪装成业务修订号。
- `epoch` 标识整体恢复 / 导入替换后的内容世代，旧客户端状态不得跨世代重新合并。
- 表格服务端引擎状态及当前投影存于 `file_contents`，持久化更新和版本另存于对应日志 / 历史表；投影不作为客户端整份回写的权威来源。
- 元数据修改与正文保存分别使用版本号，避免重命名导致正在编辑的正文无谓冲突。
- Tiptap / FortuneSheet JSON 允许经过校验的扩展字段，但限制总体积、嵌套深度及无效结构；不把任意请求字段直接写入数据库。

### 4.3 文件树与回收站规则

- 根目录的 `parent_id` 为 null；文件夹和文档可以作为父节点，表格和 PPT 不可以。
- 父子节点必须属于同一空间。禁止跨空间移动、移到自身或后代、移入已删除节点。
- 移动接口接收目标父节点与定位节点，不接收客户端生成的整棵树；服务端在事务内计算排序。
- 树移动采用同一空间级事务锁，校验循环关系并更新顺序，防止并发移动绕过校验。
- 删除父节点时，同批次软删除其有效后代。恢复按删除批次恢复，不复活此前已经单独删除的文件。
- 原父节点不存在或仍在回收站时，恢复接口返回需要选择新位置的冲突，前端让用户选择根目录或其他有效位置。
- 永久删除由负责人操作，前端明确确认；删除文件、内容、分享及个人记录。附件依据剩余引用清理，失败可重试。

## 5. 内容保存与附件

### 5.1 协作编辑与可靠保存

- 文档的权威状态为 Yjs 文档；Tiptap JSON / Markdown 从协作状态生成，用于读取、导出和历史预览。JSON 投影标记修订号，AI 和公开阅读不读取未经标记的过期投影。
- 表格的权威状态由服务端操作引擎管理；FortuneSheet 投影用于初始化、导出和历史预览，旧 Univer 快照仅用于演示数据转换。不允许浏览器周期性上传整份快照覆盖在线工作簿。
- PPT 保存原始 `.pptx`，客户端只读渲染，不进入多人编辑协议。
- 同一文件允许多个账号和同账号不同标签页编辑；房间使用服务端文件 ID 定位并校验空间。在线用户、文档光标、表格选区属于临时状态，不写历史版本。
- 文档光标位置采用协作引擎的相对位置；章节展开收起、目录开关、缩放等个人界面状态本地保存，不作为共享正文。
- 撤销 / 重做只撤销当前编辑会话自己的操作，不能撤销其他人的输入；AI 操作记录为独立来源。
- 文档高亮块、折叠块、图片、正文表格、代码块及稳定 block ID 必须验收并发行为；文档内表格属于 Tiptap 协作，独立工作簿属于表格引擎协作。
- 初次加载房间成功前不允许把旧 JSON 或本地草稿重复初始化到已有协作状态。已有 JSON 只在首次迁移时转换一次，标记完成。
- 断线时保留待同步改动，页面显示未连接 / 待同步；重新鉴权成功且 epoch 一致后重新同步。断线不能显示服务端已保存，长期离线协作不在本期范围。
- 连接建立时校验身份，成员移除、账号停用、会话撤销、文件删除时主动撤销相关连接，并在写入入口重新验证。密码验证访客只能读取，不能加入可写房间。
- 文档协作持久化保存更新日志和可恢复检查点；压缩只能在检查点成功落盘后清理已覆盖日志。表格要求选定引擎提供同等可验证的恢复能力。
- “已同步”表示服务端收到更新，“已保存”表示对应更新已持久化；普通 WebSocket ACK 或 Provider 同步事件不能直接作为数据库保存成功依据。
- 增加持久化屏障机制：浏览器提交自身已发送更新的标识，服务端确认这些更新落盘后返回修订号。具体标识按引擎实现，例如连接内更新序号 / 状态向量；不得仅发送客户端时间。
- 手动按钮和 Command / Ctrl + S 先提交当前输入，再等待同步与持久化屏障，创建有实际变化的历史检查点。失败显示可重试状态，不丢弃待同步内容。
- 页面关闭期间的释放 / 请求不作为可靠保存保证；有未同步内容时提示离开，本地草稿按账号、空间、文件、epoch 隔离。
- 日常实时操作由协作协议合并；AI 批量修改、整体导入和历史恢复通过服务端命令队列及修订检查执行，不绕过实时状态。

### 5.2 上传与授权

- 上传限制：统一上传入口的 PDF、视频、图片、PPTX、Markdown 和 XLSX 原文件均为 200 MiB；文档内插入图片和头像仍为 1 MiB。当前表格投影和单条协作消息默认各 8 MiB，可配置 1 KiB–8 MiB；文档权威状态与 JSON 投影各 8 MiB。HTTP JSON 总请求体默认 16 MiB，可配置 1–64 MiB；转换后内容仍受编辑器规模限制。HTTP 超限返回 413，前后端显示明确提示。
- 协作协议独立限制更新消息大小、发送频率和房间内容规模；不能只限制 HTTP 请求。具体值在阶段 1 根据引擎初始化消息与代表性文件确定。
- 图片第一版接受 PNG / JPEG / WebP / GIF，检查实际文件类型；PPTX 检查 OOXML ZIP 结构及必要条目。
- 存储键由服务端生成，原文件名只用于显示和下载，不作为磁盘路径。
- 附件目录不可通过公开静态路由直接访问；成员读取附件时校验空间，访客读取时校验有效分享及文件引用关系。
- 文档图片持久化为附件 ID，运行时转换为可授权读取地址；不能把临时 Blob URL 保存为正文。
- 替换 PPT 先写新文件，再提交数据库引用；提交失败清理临时文件，旧文件在成功替换后按引用清理。
- 上传未绑定附件保留短暂清理宽限期；清理任务也检查数据库引用，避免删除仍在使用的文件。
- 私有内容与受密码保护的分享响应设置不缓存；下载校验不因 MIME 或 URL 被绕过。

### 5.3 简单版本管理

- 文档和表格右上角「…」提供“版本历史”，打开右侧面板；列表展示时间、操作人、页面 / AI / 导入 / 恢复来源，手动版本支持备注。
- 选择版本使用隔离的只读查看器预览，不将旧快照载入当前可写房间；第一版不做版本差异或合并。
- 自动保存持续持久化协作更新，有变化时每 5 分钟生成历史检查点；手动保存有变化时生成独立版本，重复无变化保存不生成记录。
- 每次成功 AI 内容修改、整体导入替换和历史恢复生成独立版本；多人短时间自动更新合并为检查点，不给每个字符生成历史记录。
- 协作更新序号、已持久化 revision 和可恢复历史版本分别定义，历史版本从服务端一致的协作检查点生成。
- 历史版本完整引用所需附件；清理附件必须同时检查当前内容与所有保留历史版本，不能因当前正文删除图片而破坏旧版本。
- 每个文件最多保留最近 100 个历史版本，所有来源统一计数；写入新版本时在同一事务内清理超额版本，服务启动时也清理已有超额版本。当前内容独立保存，只释放被清理版本的附件引用，仍被当前内容或其他保留版本引用的附件不得删除。协作更新日志可独立压缩。
- 历史仅空间成员可读；恢复和备注按空间编辑权限执行，公开访客只读取当前内容，AI 第一版无恢复能力。
- 恢复前确认当前已持久化 revision。服务端临时暂停该房间写入，保存恢复前检查点，再以历史内容建立新的 epoch 并生成新历史版本，新旧检查点统一受最近 100 个版本的保留上限约束。
- 通过房间通知在线编辑者加载新 epoch；尚未同步的旧改动保留为本地副本并提示用户处理，不能自动合并回恢复后的内容。旧连接、旧 API 命令和旧重试凭证都不能再写新 epoch。
- 整体 Markdown / XLSX 导入替换使用同样的排他命令和 epoch 切换流程；普通编辑不使用单人编辑租约。
- 恢复、导入替换不是直接覆盖数据库，必须由对应协作适配层执行并在失败时保持恢复前状态可用。

## 6. 接口契约

### 6.1 通用约定

- 业务浏览器接口使用 `/api/app/`；后台业务管理接口使用 `/api/admin/`；公开分享使用 `/api/public/`；API Key 调用使用 `/api/v1/`。
- 各类认证入口明确声明身份，禁止在后台 / 前台 Cookie、分享会话和 API Key 之间自动回退。
- 请求 / 响应字段使用 camelCase；ID 使用 UUID，文本限制长度，写入对象限制额外字段。
- 分页沿用 MAS：`page`、`pageSize`，每页 1–100，返回 `items`、`total`、`page`、`pageSize`。
- 错误沿用 `code`、`message`、`requestId`，业务扩展字段按具体响应 Schema 定义。
- 401 表示未登录，403 表示无权执行操作；无权读取的资源可统一返回 404。409 表示版本或树状态冲突，413 表示大小超限，429 表示限流。

AI 文档局部修改示例（页面实时编辑走协作协议）：

```json
{
  "expectedRevision": 12,
  "expectedEpoch": 2,
  "requestId": "本次操作唯一ID",
  "operations": [
    {
      "type": "replace_text",
      "blockId": "block_intro",
      "oldText": "下周",
      "newText": "下周三"
    }
  ]
}
```

成功返回 `fileId`、新 `revision`、`epoch`、`savedAt` 和 `versionId`；冲突响应包含 `code: CONTENT_CONFLICT`、`currentRevision` 和 `currentEpoch`，不能以客户端时间戳判断新旧。epoch 不匹配要求重新读取 / 连接，不重放旧操作。

移动接口使用 `parentId`、`beforeId`（null 表示末尾）和当前元数据版本，支持移到文件夹内第一个位置；前端不能仅依据 hover 高亮判断操作成功。

### 6.3 分享与密钥处理

- 密码和 API Key 只保存哈希。分享配置查询只返回 `hasPassword`，不回传明文密码。
- 密码验证建立短期 HttpOnly 访客会话，其有效期不能超过分享有效期；修改密码、撤销或重新签发链接会使已有授权失效。
- 分享链接完整 Token 通过生成 / 重新生成响应提供，日志不记录完整 URL；日常配置查询只返回状态，不从 Token 哈希反推出链接。
- 用户丢失链接时可重新生成；旧链接立即失效。前端说明这一副作用。
- API Key 哈希用于认证，原文加密存储；创建者可单独查看，列表只显示前缀；创建者离开空间、账号停用、过期或撤销后立即不可调用。
- 密码尝试、认证和 API Key 请求分别限流；凭证、正文和数据库异常不写入普通日志。

## 7. 空间 AI 权限与 API / MCP

### 7.1 权限策略

- 空间设置统一管理 API 密钥，不再独立配置空间 AI 策略。每把密钥提供读取、创建、修改、整理、删除恢复、上传六项权限。
- API Key 绑定一个空间，默认只读，可使用权限预设或自定义权限，并支持后续修改；实际操作受密钥权限、创建者当前成员资格及文件权限共同限制。
- 提供只读助手、内容编辑、内容整理、完整文件操作预设；修改具体选项后显示自定义。负责人可管理空间全部密钥，成员仅管理自己的密钥，完整值仅创建者可查看。
- AI 不得创建 / 删除空间、管理成员 / 账号、修改空间或 AI 策略、管理密钥、修改公开分享、永久删除文件或清空回收站；第一版也不开放历史版本恢复。
- 密钥权限变化和密钥删除必须使现存 MCP 会话的工具调用立即失效，不能只在连接创建时校验。

### 7.2 内容操作契约

MCP 为主要 AI 接入体验，HTTP 为脚本和第三方集成入口。工具发现与 HTTP 契约不同，但权限、参数语义和业务实现共用。

| MCP 工具 | HTTP 接口 | 数据粒度 |
|---|---|---|
| `read_document` | `GET /api/v1/files/:id/document` | 修订号、稳定 block ID、块内容；可按块读取 |
| `update_document` | `PATCH /api/v1/files/:id/document` | 文字替换、块插入 / 替换 / 删除、块类型修改 |
| `read_workbook` | `GET /api/v1/files/:id/workbook` | 工作表 ID、范围、值 / 公式、按需格式 |
| `update_workbook` | `PATCH /api/v1/files/:id/workbook` | 单元格读写 / 清空 / 格式、插删行列、工作表管理 |

- 文档每个可操作内容块使用稳定 ID；插入新块生成 ID，协作复制 / 粘贴和批量导入不得产生重复 ID。AI 不用段落序号或字符串偏移作为长期定位。
- `replace_text` 限定块和准确旧文字，不存在或有多个匹配则返回定位错误；修改文字保留未指定格式。块插入 / 替换支持 Markdown，由服务端转换；完整替换块的格式由新内容决定。
- 工作表用稳定 `sheetId` 定位；单元格值和公式明确区分，未指定的格式保持。行列变更、引用重定位、公式计算必须经过协作引擎，不直接改快照矩阵。
- 所有写命令包含 `expectedRevision` 和 `requestId`。同一主体同一幂等键重试返回原结果；相同键不同请求体报错，不重复插入块 / 行列。
- 执行前在文件的权威协作状态上建立持久化检查点、校验修订，再在房间命令队列中验证目标并提交操作；若其间有新更新使目标版本变化，返回 409 要求重新读取。不得用过期 JSON 投影校验版本。
- 整批操作预先验证，通过后作为一个引擎事务 / 原子命令批次提交；失败不部分写入。响应在落盘后返回新修订号、修改块 / 范围和历史版本 ID。
- 操作应用于在线协作状态并广播给浏览器。AI 是独立修改来源，可显示正在执行及结果；不创建虚假的人类账号。
- 文本并发由 CRDT 合并，但 CRDT 不保证业务语义：AI 修改读过的旧内容必须拒绝或重新定位，不能以“可合并”为由忽略预期版本。
- 表格服务端命令先在权威引擎预演并验证整批操作，再提交数据库事务；事务成功后更新在线房间并广播确认。客户端 JSON 投影不参与服务端授权或代替原子批次。

### 7.3 工具与配置

- 提供文件列表、搜索、创建文档 / 表格 / 文件夹、重命名、移动、软删除 / 恢复；工具是否可执行由密钥权限和创建者文件权限决定，权限不足返回明确错误。
- 图片 / PPTX 上传使用独立 HTTP 上传接口，受附件上传权限控制；PPT 原文件替换按修订校验。第一版 MCP 不传大体积二进制参数。
- MCP 暴露 `/mcp`，Streamable HTTP 和 Bearer API Key；采用官方 SDK，限制响应大小、执行时间和单次批量操作规模。
- 设置页模板使用实际部署地址；完整密钥按需读取，不保存在浏览器持久化存储中。

## 8. 前端联调设计

### 8.1 状态与请求层

- `apps/web/src/http` 集中配置 `/api`、Cookie、CSRF、超时和错误处理；请求取消与大文件超时按接口设置。
- `src/api` 按账号、空间、文件、内容、附件、分享、历史和密钥划分接口；协作连接和状态封装在对应编辑器适配层，不由页面零散创建连接。
- Zustand 保存当前账号、当前空间和界面状态。文件和内容来自服务端，不继续把全部业务对象持久化到 localStorage。
- 主题、导航宽度等设备偏好继续本地保存；服务端内容加载和保存状态与设备偏好分离。
- 切换账号 / 空间时取消旧请求，清空相应缓存；请求返回后确认文件 ID 和空间仍匹配，避免旧响应写入新页面。
- 401 保留可恢复草稿，跳转登录并记录返回位置；403 / 404 给出访问失败界面；409 进入冲突处理；保存错误展示可重试状态。

| AI 设置 | 独立密钥六项权限、权限预设、创建 / 查看 / 修改 / 删除、到期时间、真实 API / MCP 模板 |

访客页面不挂载成员工作区布局，不显示文件树、空间设置或编辑入口。文档编辑器不可编辑，表格使用只读配置并验证所有写入口失效，PPT 复用只读组件。服务端同时禁止访客写入，不能只靠隐藏按钮。

### 8.3 演示数据迁移

- 登录后由用户主动选择导入到目标空间，不自动导入样例文件。
- 迁移原有父子关系、文档 JSON、Univer 快照和 PPTX 原文件；以旧 ID 到新 UUID 映射修正文档引用。
- 导入为新文件时初始化协作状态并生成初始版本，标记已初始化；不在用户每次打开时重复转换。
- 内嵌本地图片上传后替换为附件 ID；缺失的 IndexedDB 原文件在结果中标记，不能显示全部成功。
- 导入使用幂等键，记录各文件结果，支持失败项重试；原有本地数据直到用户主动清理前保留。
- 演示密码、公开链接和 API Key 不迁移；导入文件默认私有。

## 9. 开发、构建与部署

### 9.1 开发命令目标

- 根目录 `bun run dev` 启动前台、后台和后端；允许通过独立命令启动某个服务。
- 前台 / 后台 Vite 代理业务接口到独立后端端口；Cookie 来源和 CSRF 配置同时覆盖开发入口。
- `bun run build` 构建三部分；`bun run check` 汇总类型和必要检查；迁移沿用 `db:generate`、`db:migrate`。
- 不把当前 MAS 的单一 `PUBLIC_ORIGIN` 直接假定为支持两个 Vite 来源：整合时明确配置允许来源或统一开发代理入口，保留写请求来源校验。

### 9.2 Docker Compose

部署服务为 `web`（前台及后台静态文件、Nginx 反向代理）、`app`（Bun 后端、Hocuspocus 文档房间和 FortuneSheet 表格房间）、`postgres`，以及显式运行的一次性 `migrate` 任务。第一版只有一个 `app` 实例，同一文件只有一个进程内权威房间；不能通过增加应用副本扩容，跨实例房间路由和共享协调不在本版范围内。

- `/` 挂载前台；`/admin/` 挂载后台；`/api/` 和 `/mcp` 代理到应用；文档 / 表格协作连接均代理到单实例 `app`，配置 WebSocket 升级与心跳超时。
- 后台静态资源基础路径和 MAS `WEB_CMS_PATH` 保持一致，前台 Hash Router 保持现状。
- 数据库和附件使用独立命名卷；敏感配置通过环境变量提供。
- 迁移作为显式部署步骤或一次性任务，在应用启动前执行；不在多个服务启动时竞争迁移。
- 健康检查分别覆盖应用存活和数据库就绪，不泄漏配置。
- 附件路径、上传体积、JSON 请求体限制、反向代理超时和应用超时一致配置。
- 部署文档包含首次管理员初始化、升级、迁移失败处理及回滚约束。
- 备份覆盖业务库、协作权威存储、历史版本和附件；暂停写入包括协作连接并等待更新落盘，不能只停 HTTP 写请求。演练恢复当前内容和历史版本；仅恢复业务数据库不足以恢复完整内容。

| 0：工程整合 | 引入 MAS、前台迁至 `apps/web`、workspace、依赖、配置和启动构建命令整合 | 原前台编辑交互保持；前后台可启动 / 构建；后端健康检查与数据库迁移正常 |

阶段 0 独立验收，不以协作选型结果作为工程整合完成条件；阶段 1 在整合后的工程中使用隔离验证模块确认方案，尚不代表业务协作已交付。协作权威存储和协议定稿依赖阶段 1 结论，后续业务落地按上述阶段顺序推进。

演示导入框架及文档 / PPT 在阶段 4 完成，表格目标格式迁移在阶段 6 验收。每阶段可以展示或内测，但本版正式交付必须包含阶段 6 的表格协作和阶段 7 的整体验收。

### 10.1 验证策略

- 数据库与权限使用专用测试库，接口通过 Fastify `app.inject()` 验证，关闭应用和数据库连接。
- 必测：跨账号 / 跨空间访问、成员移除、无效分享、附件越权、只读密钥写入、树循环和并发版本冲突。
- 协作必测：双账号和同账号多标签并发、同一文字 / 单元格修改、插删行列、公式引用、个人撤销、网络中断与重连、重复更新、服务重启、数据库写入失败与不误报已保存。
- 初始化 / 导入 / 恢复验证旧 epoch 更新拒绝、未同步改动本地保留、历史图片可读、预览不污染活跃房间；历史恢复后各端收敛。
- AI 验证并发用户输入、批次原子性、幂等重试、过期修订、成员移除、密钥缩权和删除；人类和 AI 修改共用同一权威内容。
- 性能验收用每文件 10 个连接的代表性文档 / 表格，记录硬件、数据规模、同步延迟与内存；结果只适用于实际测试规模，不能据此推断无限并发。
- 上传验证伪造 MIME、无效 PPTX、替换中断、引用清理失败后的重试。
- 浏览器逐阶段验证真实接口和可见状态，不能仅以构建成功证明联调完成。
- Docker 从空环境验证迁移、账号初始化、上传、重启持久化、分享和备份恢复。

## 11. 关键风险与实施约束

- MAS 当前源码是可复用基础，不等于已具备 MinMD 空间业务。引入时固定提交并核对许可证和配置，后续升级通过差异审查。
- 本地存储迁到服务端时，保留演示数据和未保存草稿，避免把样例账号、分享密码或密钥当作真实数据。
- FortuneSheet 的操作广播不等于完整冲突变换。复杂行列 / 引用并发、个人撤销和权威公式计算仍是阶段 1 验证门槛，本版多人协作要求不因此降低。
- 协作日志、完整历史快照与大表格增加存储和计算成本；限制体积、压缩更新日志并按需加载，不把快照复制和客户端消息转发当作可靠协作。
- 新旧客户端 schema 不一致可能破坏协作内容；为连接声明 schema / 协议版本，拒绝不兼容客户端写入并提示刷新。
- PPTX 版式和字体还原继续受浏览器渲染库限制，后端存储不承诺提高还原度。
- 不用文件创建者、前端按钮隐藏或账号 metadata 替代授权；所有访问和写入规则在服务端执行。
- 正文 / 附件更新跨数据库和文件系统，采用临时文件、事务绑定和可重试清理，不宣称跨介质原子事务。
- Docker 能启动不等于可部署验收通过，必须验证真实持久化和恢复路径。
